# PhysMaster Interactive v9

这是基于 SJTU PhysMaster 的非官方扩展版本。保留上游 MIT 许可证、署名和 README；版本号属于本扩展项目。

## 从 v8.3.2 升级（已有可运行环境）

1. 在服务器终端按 `Ctrl+C` 停止服务，等待研究工作进程退出。先备份现有项目。
2. 解压 `PhysMaster-v9-upgrade.zip`，将其中的文件与文件夹合并到项目根目录。根目录是包含 `web_server.py`、`run.py`、`config.yaml` 的那一层；不能套在另一个同名子目录中。
3. 安装报告依赖。升级包不包含 `config.yaml`、API 密钥、历史 `outputs` 或个人 Prior 索引；保留这些本地文件。

   ```bat
   cd /d C:\Users\yanxiaohai\Desktop\PhysMaster-v8
   python -m pip install reportlab pypdf
   python -X utf8 web_server.py --cfg_file config.yaml
   ```

   路径替换为你的实际项目目录。如果解压到 `PhysMaster-v9`，就将路径最后一段改为 `PhysMaster-v9`。在原有 Anaconda 环境中运行即可。

4. 打开 `http://127.0.0.1:8765` 并按 `Ctrl+F5` 刷新。也可双击根目录的 `start_physmaster_utf8.cmd`；它调用当前环境中可用的 Python。
5. 创建新任务或对旧任务点击“基于旧成果继续研究”。旧结果保留；v9 不会追溯修改历史节点的分数、验收状态或文件。

模型 API 和 WebSearch 仍使用原配置。Tavily 的 `api_key_env` 填环境变量名（如 `TAVILY_API_KEY`），不能填密钥值。运行中的任务在轮间接受条件；暂停也是轮间生效。

## 全新安装

解压 `PhysMaster-v9-full.zip`，在其中的 `PhysMaster-v9` 目录打开终端：

```bat
python -m pip install -r requirements-web.txt
copy config.example.yaml config.yaml
```

编辑 `config.yaml` 配置模型密钥、服务地址和角色模型。网页输入问题即可启动；CLI 用户需另外准备 `pipeline.query_file` 指向的文本文件。完整源码包不附带模型 API 密钥、大型向量索引或科学运行结果。

## 1. 成果管理和路径

| 位置 | 用途 |
| --- | --- |
| `query/node_N/artifact_manifest.json` | 当前节点磁盘文件、声明、SHA-256、核对和验收状态 |
| `query/node_N/模型或数据文件` | 求解节点自己的产物，可能包含失败或未验收内容 |
| `query/final/` | 本次选中分支已验收文件的发布副本 |
| `query/final/manifest.json` | 发布清单，记录原节点、大小、哈希和生命周期 |
| `query/final_manifest.json` | 同一发布清单，供网页和后续研究读取 |
| `query/completion.json` | 必需文件和子任务的最终核对、缺失原因、停止原因 |
| `query/delivery_index.md` | 程序生成的成果索引，不能替代科学报告 |
| `query/trajectory.json` | 本次选中的研究轨迹 |
| `query/finalization.json` | 是否额外补交报告、节点和评审结果 |

文件生命周期为“生成 → 文件核对 → 节点验收 → 发布”。有文件不等于被验收；内容哈希、相对路径和基础格式须对应当前节点。只有本次选中分支的有效节点可以发布，其他分支、旧任务、未声明的临时文件不进入 `final/`。参数违规或缺失证据不能靠文件复制变成通过。

沿用任务根目录的归档副本以兼容旧流程，网页优先下载 `final/` 文件。下载时再次检查发布记录中的哈希；文件被修改后返回错误，避免把修改后的内容当成已核对版本。未验收的节点文件仍可下载用于排查，但会明确显示其状态。

基础文件检查包含 Python 语法、CSV 表头和数据行、JSON 解析、PDF 结构及可读页面。它不判断数据是否正确，也不能证明数学推导或物理模型成立。PDF 的版面与内容仍需检查；正式报告中保留模型适用范围和未解决问题。

## 2. 四项评分和独立验收

统一使用 0～1 分，而非 0～10 分。

| 分项 | 来源 | 默认权重 | 含义 |
| --- | --- | --- | --- |
| 科学／方法 | Critic 模型评审 | 50% | 当前子任务的方法、假设、结果与验证 |
| 文件交付 | 程序核对 | 25% | 声明文件中可核对文件的比例；代码任务无声明文件得 0 |
| 参数与证据核对 | 程序核对 | 15% | 明确通过为 1，发现违规为 0，证据不足为未评分 |
| 表达／输出结构 | 程序检查 | 10% | JSON 可解析、有实质结果字段、非失败交付；不是文风或科学质量评分 |

没有文件需求的推理节点，文件分项显示“不适用”，其余权重按比例重分配。适用分项缺失有效评分时，综合分显示“未评分”；搜索内部使用 0 作为数值占位，但网页不把它显示为真实的科学 0 分。

`reward` 是综合搜索排序分，`science_reward` 保留原科学分，`score_dimensions` 和 `reward_weights` 记录细则。历史节点没有这些字段时保留旧展示，不倒推出新的分项评分。

网页的科学通过／重做阈值仍作用于 **科学分**。验收还要求 Critic 的完成建议、无阻塞问题、程序核对通过。综合分高不能覆盖参数漂移、失效执行回执、缺失证据或未解决的物理问题。

Critic 明确按当前子任务范围评审，不要求早期推理节点交付后续报告。程序会向 Critic 提供实际节点文件及已验收前置文件的有界摘录、哈希和参数信息；摘录标注截断，仍不能代替完整人工复核。Critic 若缺乏足够证据，应返回未评分及具体原因，而非机械地给科学 0 分。

## 3. 报告专用补交

研究预算结束后，如果前面的科学、代码、数据子任务都已验收，只有最终 PDF 报告尚未交付，则派发一个额外报告节点。它读取本次已核对证据，生成报告，并通过普通 Critic 和程序核对后才能发布。

它不会补造 CSV、替代数值验证、把未验收结果写成既定结论，或自动把错误模型修成正确模型。若科学／数据仍不完整，则跳过；若报告不能通过评审，则保持“部分完成”。

可在已有 `config.yaml` 添加：

```yaml
finalization:
  enabled: true
  max_attempts: 1
```

省略时使用以上默认值。`max_attempts` 可设为 0～3；设 0 或 `enabled: false` 关闭额外节点。这些节点会额外调用模型 API，其耗时和节点记录均显示在网页中；它们在普通 `pipeline.max_rounds` 预算之外。

## 4. 网页看板

- 节点默认折叠，仅显示节点身份、状态、综合 reward 和科学分。点击展开后显示“做了什么、Critic 怎么看、学到了什么、证据与工具”、分项评分及问题分类。
- Critic 原始建议与规则处理后决定不一致时，显示实际阈值、阻塞问题或程序核对原因；不会仅凭分数猜测原因。
- 文件分别显示未核对、文件已核对、节点已验收或已发布，附原节点来源。
- 研究时间线来自实际阶段记录；旧任务没有记录时显示无记录，不补造时间。
- 原绿色任务框和节点长文本保留滚动；轮询保留展开状态和滚动位置。
- 总耗时、阶段计时和工具/API 操作计时保留，增加报告补交阶段。并行操作耗时累计不能直接当作总墙钟时间。
- 交付区域提供成果清单、成果索引和文件下载；总结继续支持 MD/TXT/HTML 下载。

问题分类依据实际记录，区分执行、交付、模型调用、评分、代码回执、参数／文件违规、缺失证据和评审问题。它是诊断线索，不是自动证明失败发生在某个物理定律上的结论。

## 5. 完成后继续研究

续研会传入原问题、累计条件、旧摘要、旧文件目录以及旧发布清单和哈希，以便优先复核和复用已有模型。旧验收不自动继承；受新条件影响的结果必须重新核对。

**此版本仍启动新的研究进程和 MCTS 树，不支持恢复已退出进程，也不保证省去全部重复计算。** 它保留成果作为有来源的研究基线，不能称为原树断点续跑。

## 6. 验证与限制

运行回归：

```bat
python -m unittest discover -s tests -v
```

网页 DOM 回归另需 Node.js 和开发依赖 `jsdom`：

```bash
npm install --no-save jsdom
node tests/test_round_dashboard.cjs
node tests/test_v9_dashboard.cjs
```

交付测试记录随安装包提供。完整流水线测试使用离线 API 替身，实际执行工作进程、Python 代码、PDF 生成、审核门禁和发布；没有调用用户的 DeepSeek/Tavily API，没有验证真实太空跳伞最大生存高度。Windows 文件锁及编码通过模拟和跨平台逻辑测试，仍需要在用户真实 Windows 环境下试跑。

Python 工具会执行模型生成的代码，沿用原项目的本地执行方式；本地网页仅监听回环地址，未加入公网部署、账号体系或计算沙箱隔离。

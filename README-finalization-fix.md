# PhysMaster v8.3.2：最终回答交付修复

本补丁针对框架的一个已确认路径：LLM 连续调用工具耗尽交互轮数后，旧实现可能返回空字符串，或返回先前的计划文字作为最终答案。它不能证明某个历史节点一定走过此路径，也不验证太空跳伞模型的科学结论。

## 修改

- `utils/llm_client.py`：保留最多 8 次模型交互的预算，将最后一轮留给禁用工具的最终回答。因此最多 7 轮可请求工具；每轮可包含多个工具调用。模型提前完成时立即返回，不额外调用。最后一轮保留全部已获得的工具结果，并要求按原系统提示的格式交付。没有对所有角色强制 JSON，Promoter 仍可输出 Markdown。
- 空回答、截断回答、其他未完成回答、最后一轮仍请求工具，会给出明确错误，不能退回先前的计划文字。截断的工具请求不会执行。无工具的单次调用也检查空回答和截断。
- `core/theoretician.py`：最终回答错误或 API/client 异常发生后，保留已经收集的工具记录，返回明确的失败 JSON。包含错误原因、已有的未验证部分回答；不代替模型编造主参数声明、文件清单或计算结果。节点日志不再将这种交付失败打印成完成。
- `utils/research_integrity.py`：失败交付 JSON 必须进入未核对状态，即使 Critic 给高分也不能验收。
- 系统提示同步说明实际轮数预算。已有文件不会删除；失败节点中的文件仍需要后续明确引用、核对与评审，不能自动成为已验收成果。

## 安装

仅安装本修复，可用 `PhysMaster-v8.3.2-finalization-fix.zip`。已经装过 v8.3.2（含 UTF-8 修复）的用户，将压缩包中的 `core`、`utils`、`prompts`、`tests` 等直接合并覆盖到项目根目录。

为减少遗漏，也提供 `PhysMaster-v8.3.2-all-fixes-upgrade.zip`：合并 v8.3.2、UTF-8、每轮任务滚动、Critic 重写决定保护、此次交付修复，适用于已有的 v8.3.1/v8.3.2 项目。两个包选一个，不需要都安装。升级包没有 `config.yaml`、API 密钥、`outputs` 或资源数据，不覆盖现有配置与成果。

等待运行结束，或停止当前任务后，在服务器窗口按 Ctrl+C。解压合并覆盖到能看到 `run.py` 和 `web_server.py` 的项目根目录，再用原来的启动命令启动；网页 Ctrl+F5 刷新。已运行完的历史节点不会被补丁改写；需继续研究或新建任务才能使用新代码。

## 验证和限制

新增测试覆盖：持续工具调用后预留交付轮、提前完成、Markdown 格式、空回答、截断、交付轮误请求工具、预算校验，以及实际运行 Python 写文件后模拟交付/API 失败，确认文件与成功执行回执仍保留且验收被阻止。

完整回归：66 项测试通过（62.432 秒）；48 个 Python 文件语法解析通过，网页 JavaScript 通过 node --check。

测试使用模拟 LLM API，Python 文件写入和子进程执行是真实执行。没有使用你的 DeepSeek 密钥运行真实模型，也没有在你的 Windows/Anaconda 上验证。非空回答仍可能格式错误或证据不足，已有审计与 Critic 继续拒绝这类输出。该补丁不保证十一份产物全部生成，不更改质量为 190 kg 的约束，也不认可历史高度、密度、Knudsen 或开伞冲击数值。

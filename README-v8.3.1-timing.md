# PhysMaster v8.3.1：运行计时增强版

在本对话提供的 v8.3.1 上增加计时，继续使用 v8.3.1 版本号。保留原有
Critic 阈值、总结下载、能力开关、历史恢复、运行中追加条件与完成后重新研究。
保留 PhysMaster 上游许可证和署名；这是非官方扩展。

## 升级已有安装

1. 等研究结束，在服务器终端按 Ctrl+C 并等待退出。备份当前项目。
2. 解压 `PhysMaster-v8.3.1-timing-upgrade.zip`，把文件按原目录结构覆盖到项目根目录。
   本包包含此前 v8.3.1 升级文件和本次计时修改，必须完整覆盖。
   特别需要一起更新 run.py、web_server.py、web/index.html、core/supervisor.py、
   utils/runtime_timing.py、utils/llm_client.py、utils/live_updates.py 与
   utils/research_monitor.py。
3. 保留原 config.yaml、outputs、知识库和 API 环境变量。config.example.yaml 只是示例，
   不要用它替换自己的 config.yaml。没有新增第三方依赖。
4. 在原来的 Python 环境、项目根目录运行：

```powershell
python web_server.py --cfg_file config.yaml
```

5. 打开 http://127.0.0.1:8765，按 Ctrl+F5。新任务在右侧“运行时长”卡片显示计时。

新安装可使用 `PhysMaster-v8.3.1-timing.zip`，完整源码包没有私有配置、输出、
虚拟环境、模型缓存或知识库资料。安装与配置步骤见 README.md。

## 显示内容与口径

- 总时长：从服务器启动本次研究进程，到进程退出；包含依赖导入、研究、暂停、
  总结和进程退出等待。任务完成或失败后固定，不继续增长。
- 运行时长：总时长减去已记录的暂停等待；包含 API／网络／并行工作进程等待，
  不是 CPU 运算时间，也不是模型生成 token 的净用时。
- 暂停等待：从工作进程在轮间真正停下，到实际恢复。点击暂停后的当前轮仍在运行，
  此时不算暂停。暂停时总时长继续增加，扣除暂停后的运行时长基本保持不变。
- 各阶段：初始化、Clarifier、Prior 背景检索、Supervisor 规划、Theoretician 求解、
  Critic 评审、Promoter 整理、追加条件后重规划、暂停、经验入库、总结、可视化等。
  阶段互斥计时，反复进入同一阶段会累加；只显示已经进入的阶段。
- Theoretician 阶段统计本批并行工作的实际等待时间及准备／收集开销，
  不把每个并行节点的时长相加。批内 Critic 和 Promoter 单独计时。
- 进程启动与退出：总时长减去流水线计时，用于显示流水线计时器启动之前的导入
  和流水线完成之后的进程退出等待。
- 展开“模型请求与工具耗时”：显示接入 LLMClient 的各角色 API 请求、WebSearch、
  arXiv、Prior、CODATA、Python 与 Skills 工具的累计时长和调用次数。
  尚未调用的操作不出现。API 请求包含接口重试与网络等待，一次包装请求内部的
  SDK 自动重试不另算次数；工具返回内部错误文本也计入调用。
- 操作耗时已经包含在各研究阶段中。并行操作、工具内的检索评审等嵌套操作可能
  重叠，因此操作表不能相加作为总时长。
- 每轮成果显示“派发后时长”：从本轮目标派发、启动节点记录，到本轮完成；
  不含此前 Supervisor 规划，含该轮求解、评审和知识整理。

后台真实计时使用单调时钟。网页每秒轮询，正在运行的阶段／操作根据最新时间样本
显示累计值；若系统时钟被人为调整，活动样本的临时显示可能偏差，已完成记录仍以
单调时钟计时结果为准。操作耗时是本程序能观测的调用耗时，不是服务商服务器内部
各步骤用时。工具或模型失败时已经经过的用时仍记录。

## 保存、续研与兼容

新任务的起止时间、总时长保存在 outputs/web/<任务编号>/task.json；阶段保存在
query/runtime.json。操作使用 query/timing_operations/<进程编号>_<唯一标记>.json，
每个进程独立写入，服务器读取后合并，避免多个进程共同修改计数。
计时文件不记录 API 密钥、提示词、工具参数或工具返回正文。

刷新、切换任务和服务器重启后，可查看正常结束任务的计时记录。
完成后“补充条件并重新研究”会新建独立任务，从零计时；前一次任务保留自己的用时，
不会将旧任务耗时混入新任务。运行中追加条件产生的重规划时间计入当前任务。
历史旧任务没有计时记录时显示“—”，不从目录或文件时间推算实际总时长。

直接运行 run.py 也写入阶段和操作计时；其流水线计时从 main 开始，
没有网页服务器记录的全进程总时长。与已有版本一样，本功能不恢复已中断的旧进程。
计时文件写入失败时记录日志并继续研究。

任务查询 API 在原字段之外增加 timing：elapsed_seconds、active_seconds、
paused_seconds、current、phases、operations、started_at、finished_at、available 等。
无历史记录的时长字段为 null。

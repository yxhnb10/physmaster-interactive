# PhysMaster v8.1：完成后补充条件并重新研究

本补丁基于 yxhnb10/physmaster-interactive 的 v8（提交 e8d9157），用于本地网页工作台。
保留上游 PhysMaster 的 MIT 许可证与署名；这不是上游官方版本。

## 安装到你已有的项目

1. 等当前研究完成，在启动服务器的终端按 Ctrl+C，等终端返回提示符。
2. 备份项目根目录的 web_server.py 和 web/index.html。
3. 解压补丁，把 web_server.py 复制到项目根目录，覆盖同名文件；
   把 web/index.html 复制到项目的 web 文件夹，覆盖同名文件。
4. 不要删除或覆盖你的 config.yaml、outputs 或知识库数据。
   tests/test_chat_server.py 可以一并复制，用于运行测试；README.md 是更新后的参考说明，
   如果你的 README 有自定义内容，可保留它并仅查看本文件。
5. 使用原来的 Python 环境重新启动：

```powershell
cd "C:\Users\yanxiaohai\Desktop\PhysMaster-dynamic-chat-v6"
python web_server.py --cfg_file config.yaml
```

路径以你的实际项目文件夹为准。原有 Tavily 环境变量仍需在启动服务器的窗口设置。
打开 http://127.0.0.1:8765 后按 Ctrl+F5 刷新。
本补丁未增加 Python 依赖。

## 完成后怎么继续

从任务列表选择已完成的研究。输入补充条件，点击“补充条件并重新研究”。
界面切换到新任务，保留原问题、此前全部追加条件（包括未及时生效的消息）及本次新条件。
新任务还携带上一轮摘要，并获知旧成果目录，便于读取、复核和复制旧代码。
旧任务和结果仍在任务列表中，新任务使用新的 UUID、研究进程和输出目录。
可以多次续研，也可以在新一轮运行时继续使用原有的轮间追加和暂停功能。

- “已纳入新任务描述”仅表示条件进入了新任务输入，不表示新模型已验证正确。
- 旧摘要被标记为待核验资料，不能当作已证实的事实。
- 不是恢复旧的 Python 进程或旧 MCTS 树；会重新规划并调用模型 API，产生新的用量。
- 仍然只允许一个研究任务运行。另一任务未完成时，续研请求会被拒绝。
- 最终总结阶段需等到“已完成”后才能启动续研。
- 上一轮摘要自动携带最多 12000 字符，完整摘要和节点文件留在原目录。
- 原问题、累计条件、摘要和续研提示合计最多 100000 字符；超出时明确报错。

## 已有结果与服务器重启

新版本将已完成任务的元信息存入 outputs/web/<UUID>/task.json。
服务重启时恢复已完成和已记录失败的任务；不自动恢复运行进程或运行中的搜索树。

兼容旧 v8 网页任务：只要原项目中保留 outputs/web/<UUID>/query.txt 和
outputs/web/<UUID>/query/summary.md，就会恢复到任务列表。
旧追加条件从 live_updates 的消息与回执中恢复。
因此安装补丁时应覆盖原项目的两个程序文件，保留原来的 outputs，避免另建空项目。
如果移动了项目，旧模型代码中硬编码的绝对文件路径可能需要人工调整。
直接用 run.py 创建的 CLI 输出暂不自动导入网页历史；可手动创建任务并带上原问题、旧摘要及新条件。

## API

POST /api/tasks/<旧任务UUID>/continue
请求 JSON：{"text": "本轮补充条件"}
成功返回 HTTP 201 和 {"id": "新任务UUID", "parent_id": "旧任务UUID"}。
沿用原有本地 Host、Origin 与 X-PhysMaster-Token 校验。
任务查询增加 parent_id 字段，用于追踪上一轮任务。

## 验证与限制

17 项自动测试覆盖原有功能，以及多次续研、条件继承、原成果保留、
旧 v8 历史恢复、服务重启后的历史恢复、单工作进程限制与 HTTP 请求校验。
研究工作进程使用模拟程序，不调用真实模型 API；这些测试不验证科学结论。
真实 Windows 环境和真实模型 API 的端到端流程仍需要在你的机器上验证。
网页仍监听 127.0.0.1，是本地服务；本补丁没有加入公网部署或用户登录功能。

# PhysMaster v9.4 Incremental

基于 v9.3 Complete 的非官方续研扩展；保留原项目的许可证和署名。

## 新增能力

- 已结束任务续研时，完整快照保存 query/ 中的程序、数据、图表、报告、合同、各节点日志/评分/失败记录，以及运行日志和任务记录。快照校验 SHA-256；文件为空或旧节点失败时仍保留其历史身份。
- 多次续研按来源任务分组保存，不反复嵌套 inherited/；升级后的首个续研也会追溯仍存在的 v9.3 父任务链。
- 原问题、全部累计条件、锁定参数仍按原有机制保留。程序独立注入 continuation_context；Clarifier 无法删掉旧文件引用。
- 增量规划要求先复用历史模型，只处理新增/受影响工作；旧评分不会直接变为新评分。实际复用方案和科学评审仍由模型完成，不能保证模型一定选择最佳最短规划。
- 每个续研节点获得有限的已验收代码预览，并有三个独立本地工具：list_inherited_files、read_inherited_file、reuse_inherited_file。即使 Python/联网关闭，本地文本检索和读取仍可用。
- reuse_inherited_file 默认复制同节点目录的依赖子目录；不覆盖当前节点的不同文件或验收回执。Python 执行器会把当前节点加入模块搜索路径，避免临时执行脚本找不到已复制模块。
- 成果交付页新增“继承与复用”，支持文件搜索/分页/下载、查看来源任务、累计条件及增量计划。提供到上下文、工具读取、复制、未受影响声明及本轮验收分别显示。
- 合并此前的历史轮次导航与重复派发修复，保留 UTF-8 执行修复。

## 使用

停止服务器后安装补丁；重启后 Ctrl+F5。选择已结束的旧任务，填写新条件并点击“基于旧成果继续研究”。首个续研自动建立完整快照；已有正在运行的任务不会热更新。

## 继承边界

- 不恢复旧进程内存、Python 会话或旧 MCTS 运行；历史树/节点记录保存在快照中。新节点使用旧成果输入和增量任务，不自动获得旧完成标志。
- 旧原始文件不修改；继承快照按哈希校验，不提供操作系统层面的不可写隔离。任意 Python 代码仍有普通本地文件权限，应遵守合同不修改旧文件的要求。
- 完整文件保存在磁盘，不把所有文件全文同时塞入模型上下文；超长资料可分页读取。预览截断不会截断磁盘资料。
- 本地 Python 任意文件读取不会被推断为“工具读取”；网页只显示程序提供预览和独立继承工具的回执。
- 复制复用、旧验收、声明不受影响均不等于本轮验收。生成结果仍须通过原有参数/执行/文件/Critic 检查。
- 同一节点依赖目录可复制；项目外库、绝对导入路径、安装环境、外部数据服务不自动复制或修复。
- API 密钥配置、全局资源库不属于研究成果快照；现有 config.yaml 保留，新任务沿用当前配置及所选能力设置。
- 无法找回已经删除且从未快照保存的更早任务；无法读取或发现快照被篡改时明确报错，不声称完整继承。
- 当前 v9.4 聚焦“任务结束后的下一次续研”。运行中追加条件保留已有继承索引，仍沿用 v9.3 的轮间重规划规则。

## 验证范围

见补丁包 validation/ 的真实测试日志。验证使用离线模型替身、真实子进程/Python/文件/HTTP，以及 jsdom 页面交互；未调用真实 DeepSeek API、未进行真实 Windows/浏览器视觉验收，也未验证太空跳伞科学结论。

# PhysMaster Interactive

**基于 PhysMaster 的非官方交互扩展版，用于本地物理建模与研究过程监看。**

本项目在 PhysMaster 的研究框架上加入网页工作台、运行中追加条件、轮间暂停与继续、每轮成果监看，以及 Windows 文件锁兼容处理。当前工程整合版本为 **v9.3 Complete Replacement**；该版本编号仅用于本扩展项目，不代表 PhysMaster 上游的官方版本。

本项目由个人维护，与上海交通大学及 PhysMaster 原团队不存在官方隶属、背书或联合发布关系。

## 快速开始

### 1. 环境与依赖

使用 Python 3.10 或更高版本，以及能够访问所选模型 API 的运行环境。若已有可运行 PhysMaster 联网版的环境，可以继续使用。

下载或克隆本仓库后，在包含 `run.py`、`web_server.py` 的项目根目录打开终端：

```bash
python -m pip install -r requirements-web.txt
```

启用 Tavily 时还需要其 SDK：

```bash
python -m pip install tavily-python
```

先验检索、索引构建、飞书机器人等依赖属于上游的可选功能；使用对应功能时需要准备相应依赖和资源。

### 2. 本地配置

复制配置示例。Windows CMD / Anaconda Prompt：

```bat
copy config.example.yaml config.yaml
```

macOS / Linux：

```bash
cp config.example.yaml config.yaml
```

编辑本地 `config.yaml` 中的模型设置：

```yaml
llm:
  base_url: "你的模型服务地址"
  api_key: "你的模型API密钥"
  model: "你的模型名称"
```

以上为字段示意，不要用它替换整个配置文件。当前版本沿用联网改进版的模型分工；更换模型服务时，也要检查 `llm.model_overrides` 和 `core/theoretician.py` 中显式指定的模型名称，并确认服务支持工具调用。

不使用网页搜索时，将 `tools.web_enabled` 设为 `false`。启用 Tavily 时使用：

```yaml
tools:
  web_enabled: true
  search_provider: tavily
  api_key_env: TAVILY_API_KEY
```

`api_key_env` 表示环境变量的名字，**不是密钥本身**。上述字段应合并到配置已有的 `tools` 节点。

在启动服务器的同一个窗口中设置搜索密钥。Windows CMD / Anaconda Prompt：

```bat
set "TAVILY_API_KEY=你的Tavily密钥"
```

Windows PowerShell：

```powershell
$env:TAVILY_API_KEY = "你的Tavily密钥"
```

macOS / Linux：

```bash
export TAVILY_API_KEY="你的Tavily密钥"
```

模型 API 密钥与 Tavily 密钥分别配置。修改环境变量后，需要重新启动服务器并创建新任务。

### 3. 启动网页

```bash
python web_server.py --cfg_file config.yaml
```

浏览器访问：<http://127.0.0.1:8765>

端口被占用时：

```bash
python web_server.py --cfg_file config.yaml --port 8766
```

随后访问 <http://127.0.0.1:8766>。网页模式不需要另外运行 `run.py`，服务器会启动独立的研究工作进程。

## 使用方式

1. 在“开始研究”输入初始问题，选择本轮能力开关，必要时填写硬性参数，再启动任务。开关默认读取本地配置，运行中固定；续研时可以调整。
2. 查看进度、日志；在“每轮成果”中跟随最新轮次或选择历史轮次。
3. 展开节点，查看实际求解输出、Critic 决策/评分、整理后的知识与生成文件。
4. 在“条件对话”提交补充或纠正条件。消息显示“已生效”后，表示条件已纳入新的任务契约。
5. 想批量应用多条条件时，先点击“本轮结束后暂停”，等待“已暂停”，提交条件后再点击“继续计算”。
6. 最终总结阶段需等待完成。任务通过、部分完成或失败后，输入新条件并点击“补充条件并重新研究”。新任务继承原问题、全部累计条件和上一轮摘要，使用新的进程和输出目录；旧结果仍可从任务列表查看。
7. 在“研究结果”选择 Markdown、TXT 或 HTML，点击“下载总结”。HTML 保留总结原文，打开后可打印为 PDF；这不等同于自动生成包含所有图件的研究报告。
8. 服务重启后可恢复已完成任务；已有 v8 网页任务需保留完整的 `outputs/web/<任务编号>/`，至少包含 `query.txt` 和 `query/summary.md`。

例如，可以先要求建立总质量 190 kg 的太空跳伞下降模型，再补充迎风面积、大气密度或热模型的要求。得到数值结果后，应结合代码、假设及评审记录检查其有效性。

条件变化会重建任务与搜索树，并获得新一版的轮数和检索预算，可能增加 API 调用费用。旧轮次保留原条件版本，不自动认定为新条件下已验证。

## 能力开关

网页设置只写入对应任务的 `web_config.yaml`，不修改你的基础 `config.yaml`。
续研默认继承上一轮的开关，也可以调整；已完成任务的原设置保持不变。
关闭 WebSearch 不会关闭 arXiv；开关不是网络隔离机制，模型 API 仍需联网。
关闭 Python 后，模型仍可输出代码和分析，但不能调用本项目的 Python 执行工具。
Skills 关闭时不提供技能摘要，也不注册技能加载工具；开启时使用本任务的配置与技能目录。
需要的 API 密钥、SDK 和索引应预先配置，勾选开关不会自动安装或申请。
详细配置、下载接口和升级说明见 [README-v8.2.md](README-v8.2.md)。

## Critic 评审阈值

在网页“Critic 评审设置”输入研究通过阈值、重做阈值和检索相关性阈值。
默认分别为 0.85、0.60、0.50，实际初始值读取本地配置；检索阈值需启用检索评审才生效。
研究通过分数只是必要条件：Critic 仍认为存在未解决问题时，不会因高分自动完成。
低于重做阈值转为重做；低于通过阈值不能标为完成；设置同时用于评审提示词与程序检查。
设置按任务保存，续研默认继承并允许修改，运行中固定。旧任务原设置保持不变。
详情和行为变化见 [README-v8.3.1.md](README-v8.3.1.md)。

## 参数约束与完成核对

v8.3.2 针对总质量被改写、未完成子任务却显示完成、报告缺失和旧目录误引用等问题加入程序检查。
网页“硬性参数”栏可填写 `total_mass = 190 kg`，一行一个数值；也可填写其他命名参数。
明确的总质量会从用户问题中识别；其他参数建议手动填写。参数与用户最新条件冲突时会拒绝启动。
运行中以用户条件为权威，仅在追加条件生效后改变锁定值，旧 Summary 不能改写这些值。

“研究通过”要求当前所选分支的所有子任务通过评审和程序核对，且要求交付的文件真实存在。
代码节点需声明主参数、提供指定 Python 数值绑定；Python 工具启用时需有成功执行回执。
高分仍有阻塞问题、缺少证据、文件未生成或轮数预算耗尽时，保留成果并显示“部分完成／待核对”。
基础检查不是物理正确性证明；完整说明、限制及升级步骤见 [README-v8.3.2.md](README-v8.3.2.md)。

## 每轮成果与输出

每轮监看记录来自实际派发目标和 MCTS 节点成果，不展示模型内部思维过程，也不人为补充未经输出支持的结论。

- 一轮可能包含多个并行节点。
- 节点执行时显示求解状态；当前批次返回后逐步显示输出、评审与知识摘要。
- Critic 的 reward 是模型评分，不是统计置信度，也不构成物理正确性的保证。
- 当前界面不流式展示模型 token 或数值仿真的每个时间步。

网页任务输出目录：

```text
outputs/web/<任务编号>/query/
```

| 文件或目录 | 内容 |
| --- | --- |
| `contract.json` | 当前结构化任务契约 |
| `node_<编号>/` | 各节点生成的代码与结果文件 |
| `research_monitor/round_XXXXXX.json` | 每轮成果记录 |
| `live_updates/` | 条件消息、回执和任务控制状态 |
| `revisions/` | 条件更新前的契约及轨迹 |
| `summary.md` | 总结，含程序生成的完成状态与核对记录 |
| `completion.json` | 子任务、参数、文件来源与 SHA-256 核对记录 |
| 根目录交付文件 | 从当前通过分支归档的真实文件，网页提供下载 |

上一级目录包含运行日志及本次任务配置。运行配置可能含密钥，不应上传整个输出目录。

## 当前限制

- 所有聊天输入仍视为任务条件，尚未实现独立的解释问答模式。
- 暂停在轮间生效，不即时中断模型请求、检索或 Python 计算。
- 未实现跨进程断点恢复、自动实验规划和参数扫描闭环。
- 当前仅允许一个网页研究任务同时运行。
- 刷新或关闭网页不会停止任务；重启后恢复已完成/已记录失败的任务，不恢复运行进程或 MCTS 搜索树。
- 完成后续研会重新规划和调用模型 API，不是原进程的断点续算。上一轮摘要最多自动携带 12000 字符，并提供完整旧成果目录供复核；累计输入总长限制为 100000 字符。
- 关闭服务时，在终端按 Ctrl+C；服务停止接收请求并等待当前工作进程完成。
- 当前服务面向本地使用，监听 `127.0.0.1`。它会执行模型生成的 Python 代码，不应直接对公网开放；公众在线服务需要另行实现身份认证、费用控制与隔离执行。

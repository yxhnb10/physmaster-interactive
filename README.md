# PhysMaster Interactive

**基于 PhysMaster 的非官方交互扩展，用网页管理物理建模、条件追加、节点评审和增量续研。**

本项目保留 PhysMaster 的研究框架，在已有联网改进版的基础上增加本地网页工作台，让研究过程、生成文件和评审结果更容易查看与追溯。

本文对应 **v9.4 Incremental + 网页修复 1**。版本号属于本扩展项目，不代表上游官方版本。仅安装 v9.4、尚未应用网页修复时，连接状态和新增验收解释可能与本文不同。

本项目由个人维护，与上海交通大学及 PhysMaster 原团队不存在官方隶属、背书或联合发布关系。

## 主要功能

| 功能 | 当前行为 |
| --- | --- |
| 网页研究工作台 | 创建任务，查看研究节点、成果交付、总结、时长和日志 |
| 运行中追加条件 | 条件排队，在轮间纳入新的任务契约，显示生效回执 |
| 暂停与继续 | 当前轮结束后暂停；可先积累多条条件，再继续计算 |
| 完成后增量续研 | 新建任务，完整保存旧成果快照，优先复用未受新条件影响的内容 |
| 历史轮次浏览 | 上一轮、下一轮和指定轮次；自动刷新保留固定历史轮次 |
| 可视化节点卡片 | 展示做了什么、评分、Critic 意见、经验、工具与文件证据 |
| 可调 Critic 阈值 | 科学通过、重做及检索相关性阈值按任务保存 |
| 参数约束 | 锁定用户指定数值，核对参数声明和指定代码绑定 |
| 有界工程修复 | 对执行、交付等问题创建修复节点；无效评审可重新评审 |
| 成果核对与下载 | 按节点、选中分支、实际文件及 SHA-256 管理交付 |
| 独立能力开关 | WebSearch、arXiv、CODATA、Python、Skills、Workflow、Prior |
| 总结下载 | Markdown、TXT、可打印 HTML |
| 运行时长 | 总时长、暂停等待、各研究阶段、模型请求与工具耗时 |
| 网页故障恢复 | 读取请求超时与重试、恢复提示、失败接口显示 |

## 安装与启动

### 1. 准备完整项目和 Python 环境

需要 Python **3.10 或更高版本**，以及可以访问所配置模型服务的环境。已有可运行的 PhysMaster 环境可以继续使用。

可以通过 GitHub 的 **Code → Download ZIP** 获取源码，也可以克隆：

```bash
git clone https://github.com/yxhnb10/physmaster-interactive.git
cd physmaster-interactive
```

请确认取得的是所需版本的完整项目。单独补丁包不能独立运行；已有 v9.3 项目需要先应用 v9.4 升级补丁，网页修复则另外替换 `web/index.html`。

在包含 `run.py`、`web_server.py` 和 `config.example.yaml` 的项目根目录打开终端。Windows CMD / Anaconda Prompt 可以使用下面的示例路径；请改为自己的实际目录：

```bat
cd /d "C:\Users\yanxiaohai\Desktop\PhysMaster-v9.4"
python -m pip install -r requirements-web.txt
```

启用 Tavily 网页搜索时，还需安装：

```bash
python -m pip install tavily-python
```

Prior 向量检索等可选功能需要另行准备依赖和索引。没有配置的能力可以先关闭。

### 2. 配置模型

首次安装时，将 `config.example.yaml` 复制为 `config.yaml`。**已有配置不要覆盖。**

Windows CMD / Anaconda Prompt：

```bat
copy config.example.yaml config.yaml
```

macOS / Linux：

```bash
cp config.example.yaml config.yaml
```

用文本编辑器打开本地 `config.yaml`，填写 `llm.base_url`、`llm.api_key` 和 `llm.model`，同时检查 `llm.model_overrides`。

当前工程使用 `deepseek-flash` 与 `deepseek-v4-pro` 分工。`core/theoretician.py` 还显式指定了这两个模型名；切换服务或模型时，不能只修改 `llm.model`，需要一并检查这些位置，并确认目标模型支持工具调用。

`config.yaml` 是私人运行配置，不要把真实密钥提交到 GitHub。

### 3. 配置网页搜索（可选）

以下字段应合并到已有的 `tools` 节点，不要删除其它配置：

```yaml
tools:
  web_enabled: true
  search_provider: tavily
  api_key_env: TAVILY_API_KEY
```

`api_key_env` 填的是**环境变量名称**，不是密钥本身。在启动服务器的同一个终端设置实际密钥。

Windows CMD / Anaconda Prompt：

```bat
set "TAVILY_API_KEY=你的Tavily密钥"
```

Windows PowerShell：

```powershell
$env:TAVILY_API_KEY = "你的Tavily密钥"
```

macOS / Linux：

```bash
export TAVILY_API_KEY="你的Tavily密钥"
```

不使用 Tavily 时，可将 `tools.web_enabled` 设为 `false`，或在网页中关闭 WebSearch。关闭 WebSearch 不会同时关闭 arXiv 检索。

### 4. 启动网页

```bash
python web_server.py --cfg_file config.yaml
```

浏览器访问：[http://127.0.0.1:8765](http://127.0.0.1:8765)。网页模式会自动启动研究工作进程，不需要另开 `run.py`。

端口被占用时，可以改用：

```bash
python web_server.py --cfg_file config.yaml --port 8766
```

随后访问 [http://127.0.0.1:8766](http://127.0.0.1:8766)。

关闭浏览器不会停止研究。停止服务器可在启动它的终端按 **Ctrl + C**；这不是网页上的即时取消计算功能。建议等研究结束后再关闭服务器或终端。

## 网页使用流程

1. 输入初始问题，选择能力开关、Critic 阈值和硬性参数，点击“开始研究”。
2. 在“研究节点”查看每轮目标，选择历史轮次或跟随最新一轮。
3. 展开节点，查看成果、评审、经验、评分细则和程序证据。
4. 需要修改条件时，在“条件对话”发送补充要求，观察“已排队”“已生效”等回执。
5. 需要一起应用多条条件时，点击“本轮结束后暂停”，等待“已暂停”，再提交条件并点击“继续计算”。
6. 本轮结束后，可下载成果和总结；继续发送新条件会创建增量续研任务。

**发送条件不等于立即生效。**条件和暂停请求都在轮间处理，不会即时打断正在进行的模型请求、工具执行或数值计算。总结阶段不接收运行中条件，需等本轮结束后再续研。

对话输入目前均按研究条件处理，没有独立的解释问答模式。

## v9.4：完整继承与增量续研

已结束的任务可以点击“基于旧成果继续研究”。新任务保留原问题、累计条件、锁定参数，并为上一轮研究文件建立经过哈希核对的完整快照。

| 继承内容 | 处理方式 |
| --- | --- |
| 代码、数据、图表、报告 | 保存文件快照，供新节点读取或复制复用 |
| 契约、条件、节点输出、评分、评审和失败记录 | 保存来源与历史状态，便于追溯 |
| 多代续研成果 | 按来源任务组织，不反复嵌套复制历史目录 |
| 历史验收结果 | 保留原记录，不能自动变为新条件下的验收 |
| 私人 API 配置与全局知识资源 | 不作为研究成果复制；新任务使用当前运行配置 |

继承文件提供三个本地工具：`list_inherited_files`、`read_inherited_file`、`reuse_inherited_file`。关闭 Python 执行或联网后，这些继承工具仍可读取本地历史资料；关闭 Python 则不能通过本项目的执行工具运行代码。

“完整继承”表示研究资料被保存且可以访问，并不表示所有文件全文同时放进模型上下文，也不恢复旧 Python 会话、工作进程或 MCTS 执行状态。新任务会重新规划并调用模型 API，优先复用未受影响的内容，对新增或受影响的部分继续研究。

在“成果交付 → 继承与复用”中，可查看来源任务、累计条件、增量计划、文件和使用回执。以下状态分别记录：提供到上下文、工具读取、复制复用、声明不受影响、本轮验收。**复制文件或保留旧评分，都不代表本轮已经通过。**

磁盘上的完整文件不受摘要预览长度限制。旧任务被删除且没有快照时，程序无法找回其成果；项目外依赖和外部数据服务也不会随文件快照自动安装。

运行中追加条件仍沿用轮间重新规划机制。v9.4 的完整快照主要面向已结束任务开启的下一次续研。

详见 [README-v9.4.md](README-v9.4.md)。

## 评分、Critic 与验收

### 科学分和综合 reward

节点卡片的大字 reward 是**综合排序分**，用于 MCTS 比较研究尝试。科学通过和重做阈值只作用于**科学分**。

| 分项 | 基础权重 | 依据 |
| --- | ---: | --- |
| 科学／方法 | 50% | Critic 对当前子任务的评审 |
| 文件交付 | 20% | 声明文件的核对记录 |
| 执行回执 | 10% | Python 执行退出状态 |
| 参数与证据 | 15% | 程序核对结果 |
| 表达／输出结构 | 5% | 可解析结果、实质内容和交付结构 |

不适用分项会重新归一权重。适用分项缺少有效评分时，综合分不能完整计算；界面显示未评分，搜索内部可能使用 0 占位。它与“Critic 确实给了科学 0 分”是不同情况。

这些分数不是统计置信度；执行成功、文件存在或综合高分都不构成物理正确性证明。

### 达到阈值为什么仍可能需要修订？

例如科学分为 **0.78**，通过阈值为 **0.75**，仅表示分数条件已满足。完成还需要 Critic 建议 `complete`、没有未解决的关键问题，并且通过程序证据核对。

| 状态 | 含义 |
| --- | --- |
| `complete` | 通过评审规则后的完成决定，仍需结合程序核对与任务交付 |
| `to_revise` | 保留当前方向，继续修订或补足证据 |
| `to_redraft` | 需要重做；可能来自低科学分、Critic 建议或程序违规 |

高分不会把 Critic 的修订建议自动升级为完成。评审缺少必要字段、文件未核实或参数不一致，也会阻止验收。

阈值用于新建或续研任务，运行中固定。判断旧节点时应查看该节点记录的 `critic_policy`，不能用网页当前输入框的值代替历史阈值。

网页修复 1 会在折叠卡片中显示实际阈值和未通过原因；展开后显示“验收依据”。如果历史记录没有明确原因，页面会说明缺少记录，不会编造解释。

### 研究完成与文件交付

“研究通过”要求当前选中分支的子任务通过评审和程序核对，并满足任务契约中的交付要求。轮数耗尽、关键问题未解决或报告缺失时，可以保留已验收成果，但整体仍显示“部分完成／待核对”。

节点目录中的文件可能是中间产物或失败尝试。文件通过基础核对、节点被验收、文件最终发布，是不同状态。不要把“磁盘上存在文件”直接等同于“任务已经完成”。

## 能力开关与参数

能力选择写入本次任务的 `web_config.yaml`，不修改基础 `config.yaml`。续研默认继承上次设置，也可以调整；运行中的任务不会即时切换。

| 开关 | 用途与准备 |
| --- | --- |
| WebSearch | 调用配置的网页搜索服务；需要 SDK 和有效密钥 |
| arXiv | 独立联网论文检索 |
| CODATA | 查询本地物理常数表 |
| Python | 执行模型生成的代码；所需计算库应已安装 |
| Skills | 提供技能说明和技能文件加载工具 |
| Workflow | 匹配已有研究流程 |
| Prior | 检索预先准备的向量知识库；需要索引、嵌入模型及相关依赖 |

联网搜索和 Prior 检索来源不同，可以按任务组合使用。勾选开关不会自动安装依赖、申请密钥或构建知识库，关闭某个工具也不等于完全断网。

“硬性参数”支持每行一个数值，例如：

```text
total_mass = 190 kg
nose_radius = 0.5 m
```

原问题中明确的总质量会尝试自动识别，其它参数建议手动填写。主情景和补充情景应分开声明；旧摘要不能自行改写用户锁定值。程序检查参数声明和指定代码绑定，不保证理解任意代码的全部物理语义。

并行数和轮数在 `config.yaml` 中配置，例如：

```yaml
pipeline:
  parallel_processes: 2
  max_rounds: 6
```

并行求解、修复和重新评审都会增加模型请求；并行数提高不保证运行时间按比例缩短。操作累计耗时可能重叠，不能简单相加作为总时长。

## 输出与下载

网页任务主要输出位于 `outputs/web/<任务编号>/query/`：

| 文件或目录 | 内容 |
| --- | --- |
| `contract.json` | 当前任务契约 |
| `node_<编号>/` | 各研究尝试的代码、结果、评审相关文件 |
| `research_monitor/` | 每轮成果监看记录 |
| `live_updates/` | 条件队列、回执和控制状态 |
| `revisions/` | 条件变化前的记录 |
| `inherited/` | 按来源任务保存的历史成果快照 |
| `inheritance.json`、`inherited_index.md` | 继承清单与索引 |
| `summary.md` | 本轮总结 |
| `completion.json` | 完成核对记录 |
| `final/`、`final_manifest.json` | 实际发布的成果及清单 |
| `delivery_index.md` | 文件交付索引 |

“研究总结”支持下载 Markdown、TXT 和 HTML。HTML 可在浏览器中打印为 PDF，但不是自动排版的完整科学报告；任务明确要求 PDF 报告时，仍需单独生成并核对相应文件。

保留完整任务目录，才能继续查看历史记录或续研。服务器重启后可以重新读取已有记录，但不会恢复已退出进程的执行状态。

任务上一级目录中的运行配置可能包含 API 密钥，不要直接把整个 `outputs` 目录上传到公开仓库。

## 常见问题

### `provider=tavily failed: env ... not set`

检查 `tools.api_key_env` 是否为环境变量名称，例如 `TAVILY_API_KEY`。如果它填成实际密钥，程序会把密钥当作变量名查找，因而报未设置。设置环境变量后，重新启动服务器并创建新任务。

### 网页出现 `Failed to fetch` 或“页面刷新暂时失败”

先看研究记录是否仍在更新，再查看连接状态栏显示的失败接口和服务器终端。服务器进程存在，不代表每个请求都能正常返回。

网页修复 1 会对 GET 读取失败进行有界重试，连续失败时延长刷新间隔，恢复后更新提示，并保留已显示的记录。发送条件等 POST 操作不会自动重发；回复丢失时，先核对条件列表或历史任务，避免重复提交。

这个补丁改善网页处理，不能替代对后端异常或网络问题的排查。

### 修改网页后没有变化

确认替换的是正在运行项目的 `web/index.html`，然后按 **Ctrl + F5**。网页修复 1 安装成功后，右上角显示“本地运行 · 网页修复 1”。

### reward 为 0 或一轮全部未通过

展开科学分、各评分维度、Critic 意见和程序核对记录，区分科学低分、执行失败、无效评审、缺少文件与未评分占位。排查具体原因，不能仅靠降低阈值认定研究完成。

### 文件存在，却没有被验收

核对节点声明路径、所属节点目录、文件格式、内容和哈希。程序需要文件与当前节点结果建立可追溯的关系，不会自动把任意目录中的同名文件算作当前节点交付。

## 测试与当前限制

v9.4 开发版本通过 **141 项 Python 自动测试**。在其基础上的网页修复 1 通过 **6 个脚本、37 组 DOM 检查**，覆盖故障恢复、超时与重试、验收解释、历史轮次浏览、节点展开状态及继承页面。

这些验证包括离线模型替身、真实子进程、Python 执行、文件、HTTP 和模拟 DOM 交互；没有使用真实 DeepSeek/Tavily API 完整验证科研流程，也没有完成真实 Windows 文件锁环境和浏览器视觉验收。测试通过不代表生成的科学结论已经独立验证。

Python 测试命令：

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

当前边界：

- 网页服务器只允许一个研究任务同时运行；该任务内可以有多个并行求解节点。
- 暂停、追加条件在轮间生效，没有即时取消长计算的网页接口。
- 续研不恢复旧进程内存或旧 MCTS 执行状态；模型也不保证总能选出最省时的增量方案。
- 自动修复和报告补交有次数上限，用尽后保留失败或部分完成状态，不强制通过。
- 生成代码在本地环境执行。当前服务监听 `127.0.0.1`，面向本地使用；面向公众的网站需要另外设计认证、费用控制和隔离执行。

工程细节可参阅 [README-v9.3.md](README-v9.3.md) 和 [README-v9.4.md](README-v9.4.md)。

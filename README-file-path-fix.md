# PhysMaster v8.3.2：节点文件声明路径修复

针对实际文件位于 `query/node_1/model_log.txt`，但节点 JSON 把文件声明为 `query/model_log.txt` 的情况。旧核对把目录不符、不存在、空文件合并成同一条报错，容易误判为未生成成果。

## 修改

1. 评审前增加有限的路径修正：文件名必须在合同 expected_output 内，原声明必须指向当前任务根目录，且当前节点存在非空、非符号链接的同名文件。若根目录也有同名文件，其 SHA-256 必须与节点文件相同。满足这些条件才将 files/parameter_evidence.file 改为当前节点相对路径。
2. 修正不复制文件、不补造参数、不推断计算结果。真实代码的参数绑定、Python 退出回执、文件内容和最终格式仍按原规则核对。参数漂移或执行失败仍不能验收。
3. 修正记录包含原声明、实际节点路径和 SHA-256，保存在结果 path_corrections 中；网页「证据与工具」显示明确修正记录。原始求解回答仍保留为节点 theoretician_output。
4. 求解节点收到独立的合同副本：expected_output.resolved_path 指向自己的节点目录，final_archive_path 明确交给程序管理。统一系统提示要求写入 current_node_dir/output_dir，并返回相对文件名。原始任务合同与总质量等条件不改变。
5. 错误诊断分别说明文件不存在、为空、不是文件或路径不属于当前节点，不再将它们混成一句。

旧任务、其它节点、未列入合同的同名文件不能用于这种自动修正；当前节点文件缺失/为空、符号链接、现有归档文件内容不一致时也不会修正。正常的节点相对路径不受影响。

## 安装

`PhysMaster-v8.3.2-file-path-upgrade.zip` 是合并升级包：保留此前 v8.3.2、UTF-8、Critic 决定保护、最终回答交付、节点卡片折叠与决定调整原因等修改，并加入本次路径修复。

这是后端修改，需要让当前研究结束或停止任务，再在服务器窗口 Ctrl+C。解压后将包内文件合并覆盖到项目根目录（能看到 run.py、web_server.py 的目录），再按原命令启动服务器，网页 Ctrl+F5。

例如项目根目录：`C:\Users\yanxiaohai\Desktop\PhysMaster-v8`。

包内没有 config.yaml、API 密钥、outputs 或资源数据，不覆盖现有配置和成果。不要把 web/index.html 单独替换就认为后端路径修复已生效。

本修复作用于后续节点/新任务；历史节点已有的评分和审计记录不会自动改写。重新研究时，旧文件仍需作为参考读取并按新节点规则重新核对。

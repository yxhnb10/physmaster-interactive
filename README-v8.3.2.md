# PhysMaster Interactive v8.3.2

本版本在 v8.3.1 计时增强版上改进参数约束、评审推进和文件交付检查，保留计时、能力开关、Critic 阈值、追加条件及完成后续研功能。不新增第三方依赖。

## 针对本次测试的改动

| 测试问题 | 新行为 |
| --- | --- |
| 主问题总质量 190 kg，TPS 情景被改成 210 kg | 从用户输入保存总质量锁定值；核对主参数声明与指定代码绑定。辅助情景可改变参数，但不能替代主问题答案 |
| Critic 分数较高，但仍要求修订 | 必须同时满足阈值、accept、complete、有效分数和程序核对通过；非空 blocking_issues 阻止完成 |
| 连续失败后强行推进 | 移除 CLI 的失败次数强制推进；前置子任务未通过不允许跳到后续子任务 |
| 高分未通过结果作为可靠知识回传 | 只有通过评审与核对的节点能作为 Reviewed Knowledge 回传；未通过知识明确标记为未接受尝试 |
| 代码执行失败但留下打印数字 | Python 工具记录实际退出码；启用 Python 的代码子任务必须有成功回执，最后一次失败需重算 |
| 最后分析未执行、PDF 未生成却显示完成 | 逐项检查当前分支的子任务与合同文件；缺失时显示部分完成并记录停止原因 |
| 最终路径指向旧任务 | 合同文件名归属本次目录；只从当前所选通过分支归档实际文件，并核对 SHA-256 |
| Summary 把未通过尝试写成最终结论 | 提示 Summarizer 使用核对记录；程序附上状态、锁定值、缺失文件及来源，对明显总质量文本冲突降级 |

未全部通过最终核对的结果不会写入新的 L3 Wisdom。已有知识条目不会自动清理或重新验证。

## 如何升级

1. 等当前研究结束，在服务器终端按 Ctrl+C，等待服务退出。
2. 备份项目。把 `PhysMaster-v8.3.2-upgrade.zip` 的内容解压到现有项目根目录，允许覆盖同名文件。根目录应直接包含 `run.py` 与 `web_server.py`，不要再套一层目录。
3. 保留自己的 `config.yaml`、API 环境变量、知识资源和 `outputs`；升级包不包含它们。新增配置是可选的，不需要重做配置。
4. 在原 Python 环境、项目根目录运行：

```bat
python web_server.py --cfg_file config.yaml
```

5. 打开 http://127.0.0.1:8765 ，按 Ctrl+F5 刷新。标题应显示 v8.3.2。

完整包可用于新目录部署；复制配置示例并填写服务配置，安装方法见 README.md。已有项目建议使用升级包。

## 使用硬性参数

网页新增“硬性参数”文本框。每行一个参数，例如：

```text
total_mass = 190 kg
nose_radius = 0.5 m
body_CdA = 0.7 m²
```

只接受有限数值，不接受表达式、范围或容差。名称支持字母、数字、下划线或中文；质量名称 mass、mass_kg、total_mass_kg、总质量统一为 total_mass。可接受科学计数法和简单单位。kg/g 等受支持单位可转换核对，其余单位需要一致。

明确的 `总质量190 kg`、`total mass ...190 kg`、`190 kg skydiver ... system` 等用户原文会被识别。其他数值及不明确的质量描述请手动填写；本版本没有自动理解所有自然语言约束。同一条输入含多个总质量时需明确主质量，或用参数栏指定主质量。若问题明确写 190 kg 而参数栏填 210 kg，会拒绝启动；请先统一要求。

总质量指系统合计，增加热防护不能自行改变这个值。可另做明确标为 supplementary/sensitivity 的改变质量实验，主结果仍需遵守原值。非数值要求和科学可行性继续由模型评审。

运行中参数栏固定。条件对话可提交“总质量改为200 kg”，在轮间回执生效后更新契约并重建搜索树；暂停时尚未生效的消息不会提前修改锁定值。完成后可在续研时修改；保留原参数栏内容并追加明确改质量条件时，会按最新用户条件更新。若同时修改参数栏与条件，请保持一致。

CLI 也可以在配置中增加：

```yaml
integrity:
  hard_parameter_text: |
    total_mass = 190 kg
```

这是用户配置，不应交给生成的 Summary 修改；本轮契约保存在 contract.json。

## 代码和评审证据

Theoretician 的 JSON 结果需包含 primary_parameters；代码子任务还需提供 parameter_evidence。例如：

```json
{
  "primary_parameters": {"total_mass": {"value": 190, "unit": "kg"}},
  "parameter_evidence": {"total_mass": {"file": "model.py", "symbol": "TOTAL_MASS", "unit": "kg"}},
  "files": ["model.py", "results.csv"]
}
```

指定文件必须真实存在于当前节点。符号须是模块级或 Class.field 数值赋值，支持常数和简单加减乘除；无法静态核对的动态表达式、函数内变量会显示证据不足。模型须把主参数暴露为实际使用的权威常量，不能仅建立一个无关常量。

检查器不会完整追踪数据流，也不能证明声明值就是所有函数实际使用的值。Python 回执证明工具进程退出状态，不证明某个打印结果或物理公式正确。关闭 Python 工具时不会要求不存在的执行回执，但仍检查代码绑定与文件，并由评审判断未执行是否足够。

## 研究通过、部分完成和交付

进程正常退出不再直接等同于研究通过。最终 completion.json 记录每个子任务及文件状态。只核对所选轨迹的当前有效节点；回头修订前置子任务会使旧的后续接受状态失效。其他分支、未通过节点和旧任务文件不能代替本轮交付。

明确要求 PDF 时，必要时添加最终分析与报告子任务。程序不会伪造 PDF，也不会用网页的“打印总结”冒充研究报告。文件需要模型通过工具实际生成，列入节点 files，并通过最终检查。可用的文件归档到本轮 query 根目录，网页“约束核对与文件交付”卡片提供下载。归档时核对哈希；下载已归档文件时也检查它未被改动。

当前基础格式检查：Python 语法、CSV 非空表头与至少一行数据、PDF 文件头及结束标记；其他支持文件只核对存在、非空、来源和哈希。PDF 检查不验证页面布局、全部结构或报告内容。Summary 下载 MD/TXT/HTML 功能仍保留，部分完成时同样可下载。

达到 max_rounds、无可选节点、未通过评审、证据不足或文件缺失时，保留已有成果并显示“部分完成／待核对”，不会擅自增加轮数和 API 花费。需要更多轮数时自行调整配置，或针对核对问题追加条件重新研究。续研仍启动新进程、新搜索树和新目录，并继承原问题及累计条件；它不是断点续算。上一轮 Summary 仅作参考，不能改写用户锁定参数。

旧历史记录没有 completion.json 时显示“旧记录未核对”，不追溯认定旧结果已通过。更新代码不会重算这次测试，也不会自动修改旧文件里的 210 kg 或补出旧报告；需重新研究。
